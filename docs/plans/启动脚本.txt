# ═══════════ 生产部署(服务器,云汉内部分发,不发公共npm) ═══════════
# 产物 = 编译产物 lib/ + 实体化 node_modules,无源码无测试。
# 重要: 产物不可跨平台复用——native 二进制(node-pty prebuilds/koffi 平台包等)按执行 deploy 的机器平台安装
# (deploy 时 darwin/linux 平台包被跳过,见 WARN "Unsupported platform")。目标服务器是什么平台,就在同平台环境执行 deploy。
#
# [共同步骤|构建机(与目标服务器同平台,需完整仓库+pnpm)]
#   1. pnpm install + pnpm run build (bundle 依赖变更后必须重跑,否则 deploy 闭包不带新包)
#   2. pnpm --filter @deepseek-ai/dsh deploy --prod <产物目录>
#      - 目标目录不能是盘符根下一级(D:\DSH-runtime 会报 EPERM mkdir 'D:\',pnpm 11 Windows bug),放深一层即可
#      - 产物里的 pnpm-workspace.yaml/pnpm-lock.yaml 是 deploy 机制组成部分,勿删(删了重装会报 cosmokit workspace 错)
#   3. 验证闭包: 产物 node_modules\.pnpm 里应有 dsh-llm-pi-ai/dsh-knowledge/dsh-backend-task 虚拟目录
#   4. 整目录打 zip/tar 拷服务器(node_modules 必须一起带),服务器只需 Node 22.19+/24,无需 pnpm
#
# [Windows 服务器]
#   deploy 末尾的 [ERR_PNPM_IGNORED_BUILDS] dsh-subprocess-local 直接忽略:
#   该 postinstall 是恢复 node-pty macOS spawn helper 可执行位,Windows 上空转退出(no-op),不修不影响运行。
#   服务器解压后设好环境变量(见上方环境变量段)直接跑:
node D:\DSH-runtime\backend\lib\bin.js --profile enterprise-backend
#
# [Linux 服务器(将来如需)]
#   1. 在 Linux 构建机装 Node 22.19+/24 + pnpm(corepack enable),检出仓库后执行与上面相同的 build+deploy
#      (Linux 上产物自动带 Linux 的 node-pty/koffi 二进制,spawn helper 也在)
#   2. deploy 末尾的 [ERR_PNPM_IGNORED_BUILDS] 在 Linux 上必须处理(不能忽略):
#      把产物 pnpm-workspace.yaml 里 '...dsh-subprocess-local...: set this to true or false' 占位行改为 true,
#      然后在产物目录跑 pnpm install —— 否则 spawn helper 无执行权限,PTY 会话全挂
#   3. 打 tar 拷服务器解压,设好环境变量后:
#      node /opt/dsh-runtime/backend/lib/bin.js --profile enterprise-backend
#
