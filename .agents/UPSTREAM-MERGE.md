# Upstream merge-preserve deviations

Core `packages/` normally tracks upstream verbatim; the deviations below are deliberate and must survive every upstream merge. [AGENTS.md](../AGENTS.md) points here. On conflict, keep the local form unless the upstream change supersedes the reason recorded here.

- `packages/core/tools/src/index.ts` — `TOOL_RUNTIME_SCHEDULER` is a namespaced **string** key, not `Symbol()`. Source launches load plugin entries from `lib/` through the cordis loader while tsconfig `paths` resolves the same package's cross-package imports to `src/`, so two module instances coexist and a Symbol key never matches (`ctx.tools[TOOL_RUNTIME_SCHEDULER]` is `undefined`; every tool call dies with `Cannot read properties of undefined (reading 'prepare')`). Upstream's own test and launch paths are plane-consistent, so they never observe this. Reverting to a Symbol reintroduces the crash under `pnpm dsh` with a built `lib/`.

- `scripts/translation-pairing.manifest.json` — the `excluded` list carries `docs/plans/` and `apps/web-console/frontend/README.md`. Enterprise design documents and the web-console frontend README are enterprise-local, Chinese-untranslated by decision; the corpus-wide bilingual gate would otherwise reject them. When merging an upstream change to this manifest, keep these entries alongside upstream additions.

- `scripts/doc-budgets.manifest.json` — the `AGENTS.md` ceiling is raised to 1990 because the fork adds one pointer line (to `.agents/GATE-STANDARDS.md`) under "Run relevant checks locally". When merging an upstream change to this manifest, resolve the `AGENTS.md` ceiling to the larger of the two values, then verify against the merged AGENTS.md word count and raise further if it demands.

- `packages/client/ui-sidebar-right/src/client/session-views.ts` — `SidebarSessionViews.mount()` returns a no-op disposer for a reference that is no longer in `viewsByReference` (pruned view or post-shutdown), instead of throwing. Upstream throws `Sidebar Session view reference is no longer owned` in React's commit phase (RightbarRoot's `mountView` layout effect); the slot error boundary catches it and unmounts the whole `rightbar` slot entry with no retry, so one rapid session switch (`openSession` → `replaceMain` retention publish → `publishMain` → `select` → prune of a view whose React commit is still in flight) permanently kills the right sidebar until reload, while the persisted `expanded=true` hides the expand button. On merge, verify the throw has not returned: after merging, grep `session-views.ts` for `no longer owned` (expect absent) and rerun `cd packages/client/ui-sidebar-right && node ../../node_modules/pnpm/bin/pnpm.cjs bundle`. Suitable for an upstream PR.

- `packages/client/ui-sidebar-files/` — the enterprise per-file-row action slot `sidebar.files.entry.action` (trailing controls on each listed file row; `ui-enterprise` KbUploadAction occupies it — design in [notes/implemented/architecture/2026-09-12-file-row-action-slot.md](notes/implemented/architecture/2026-09-12-file-row-action-slot.md)) coexists with upstream's `sidebar.right.tab.files.actions` (header workspace-directory actions): they are different slots, never a rename. On merge, keep both: `FilesBody.tsx` holds one union `PropsRenderSlots<'sidebar.files.entry.action' | 'sidebar.right.tab.files.actions'>` plus both dispatch sites (row-level `renderAction`, header `renderSlot`), `index.ts` registers both under `children`, `tests/mount.client.tsx` keeps a single recording `renderSlot` that filters to the entry-action key, and `apply.client.spec.ts` asserts both children.

- `packages/session/session-persistence/src/index.ts`, `packages/session/session-persistence-jsonl/src/{index,storage}.ts`, `packages/session/session-projection-cache/src/index.ts` — new deletion-path APIs: `SessionPersistence.discardPendingSession` (default no-op; JSONL override drops the tracker's created-but-unmaterialized registration, refusing while a write claim holds the id) and `SessionProjectionCache.drop` (durable per-record removal). Upstream's delete story has no consumer for these, but without them a session deleted through the enterprise delete endpoint stays listed: the JSONL backend's `list()` serves pending in-process registrations by contract even when the artifact directory is gone, and the projection cache keeps serving the cached listing row, so the deleted session reappears in the client ("删除成功" then back under 未分组). All three changes are purely additive (default no-op, new methods); on merge, if upstream grows its own deletion lifecycle, prefer upstream's and retire these. Suitable for an upstream PR.

- `packages/client/ui-slots/src/index.ts`, `packages/client/ui-settings-general/src/client/{shell-contract.ts,index.ts,SettingsRoot.tsx}`, `packages/client/ui-primitives/src/icons/index.tsx` — settings.section list-slot entries accept an optional `icon?: SlotIcon` thunk (mirrors the thunked `SlotLabel`): ui-slots stores it in registration options and exposes the `SlotIcon` type; ui-settings-general projects it onto `SettingsSectionRow.icon` and `navIcon` renders a contributor icon before its built-in id mapping (gear fallback stays for ids with none); ui-enterprise (not itself a deviation) registers API/phone glyphs for its `enterprise-services`/`pocket-access` sections, with the new `IconPhoneOutlineRegular`/`IconPhoneOutlineMedium` added to ui-primitives. Upstream's shell hardcodes nav glyphs for its five built-in section ids and every other id renders the fallback gear, so without the options channel the enterprise sections are indistinguishable from 通用设置. On merge, keep the options field, the row projection, the `row.icon` branch in `navIcon`, and the phone icon; if upstream grows its own icon option, prefer upstream's and retire these. Suitable for an upstream PR.

- `packages/client/ui-workspace/src/client/contract/slots.ts`, `packages/client/ui-directory-picker-{browse,native}/src/client/index.ts`, `packages/client/ui-directory-picker-{browse,native}/tests/client-flow.client.spec.tsx` — the third directory-flow hole `sidebar.nav.directoryFlow`. The enterprise task-queue sidebar's workspace-picker dialog (`ui-enterprise` `WorkspacePickerDialog`, itself not a deviation) is a third trigger surface for the shipped picking interaction; upstream's contract ships only the two trigger-surface holes, and a third surface cannot reuse either: a hole has exactly one declaring entry, and occupancy rides the inject face's `hooks.directoryFlow`, so each surface needs its own hole. Without it the dialog must call a capability verb directly (`uiWorkspace.pickDirectory()`), pinning the native gear and crashing under the enterprise bundle's browse pin (`directoryPicker.pick needs the native capability`). On merge, keep: the SlotMap row, the `DirectoryFlowSlotName` member, and the three-registration doc block in `contract/slots.ts`; the third `ctx.slots.inject` nesting level plus third `register` row in both flow packages' apply (the trio is one transaction; nesting order is arbitrary); both specs' three-name `HOLES` arrays, the "fills all three" case, and the rival injection covering all three holes. Suitable for an upstream PR: purely additive, and the hole mechanism exists precisely so a third-party surface composes the shipped picker without branching on a capability kind.

- `AGENTS.md` — the fork's condensed form: no package-groups list under Repository layout (the `Package groups: [packages/README.md](packages/README.md).` pointer line carries it) and the Acknowledge/Record paragraphs merged into one (`Acknowledge [declared persistence-type changes](...) and record each externally perceptible breaking change ...`). Upstream keeps the full groups list and the two separate paragraphs. On merge, keep the fork's condensed form and take upstream's surrounding content verbatim (commands, error-handling and artwork rules, pointer targets); upstream edits inside the groups list or inside the Acknowledge/Record paragraphs land only where they change shared pointer-line content. The `GATE-STANDARDS.md` pointer line and the raised `doc-budgets` ceiling are covered by their own entries; `.agents/GATE-STANDARDS.md` itself is fork-only.

- `scripts/verify-client-ui-i18n.ts` — the gate's file discovery excludes `packages/client/ui-enterprise/`. The enterprise workbench is a Chinese-only surface: its copy is hardcoded Chinese by product decision, it ships no locale dictionaries, and the web-console frontend is already outside the gate's scope by the same policy (its globs never covered `apps/web-console/`). On merge, keep the enterprise exclusion filter; if upstream grows a first-class exempt-list mechanism, prefer it and retire the filter. The 392 recorded violations (2026-10-24) are the pre-exclusion inventory.

- `scripts/verify-node-next-types.ts` — the consumer `node_modules` linking uses junctions on Windows (`linkKind = 'junction'` passed to both `symlinkSync` calls). On this fork's Windows hosts with developer mode enabled, `symlinkSync` reports `ENOENT` on the call it just completed (the link exists; `lstat` in a follow-up step still fails) under Node 22 and 24 alike, so the gate dies on its first package. Junctions need no privilege, take absolute targets, and resolve identically for the consumer typecheck — npm and pnpm link workspace packages on Windows the same way. On merge, keep the `linkKind` constant and both call sites; if upstream moves to a `cpSync`/real-directory layout or another link mechanism, prefer upstream's.

- `scripts/verify-repository-references.ts` — `isLockFile` exempts `*.lock` files from the commit-hash check (the organization-URL check still applies). Machine-generated dependency locks carry size- and checksum-shaped decimal runs (`uv.lock` wheel sizes are seven-digit decimals) that once the object database grows past tens of thousands of commits collide with a 7-digit commit abbreviation — a pure false positive with no authored reference (the first observed collision came from a wheel size matching the abbreviation of a commit the upstream merge introduced). Do not quote the colliding digits in this file: the gate scans it too. On merge, keep the `isLockFile` filter in both the candidate extraction and the scan; if upstream adopts its own lock-file exemption, prefer upstream's.

- `scripts/gen-cli-help.ts` — the per-invocation child environment sets `DSH_BACKEND_PORT: '0'` and `DSH_LOG_LEVEL: '-1'`, and the child timeout is 120s instead of 30s. Help collection boots profiles for real, and the overrides exist because the fork's profiles boot enterprise bundles: the host machine may run a resident enterprise-backend instance on the default port (3190), so without the wildcard port the `enterprise-backend --help` boot fails with `EADDRINUSE`; enterprise bundles mount a stdout logger exporter whose runtime diagnostics carry timestamps, so any captured line would make the collected help nondeterministic (error is level 0, so -1 drops every record); and the enterprise profile cold-boots the web and enterprise-app trees through tsx, so under doc-sync's worker concurrency a source launch can exceed 30s. Neither override reaches the recorded output (the help text never includes the runtime port; logger records never reach the collected help stream). On merge, keep the env overrides and the timeout; if upstream grows a general profile-isolation or log-silencing mechanism for help collection, prefer it and retire these.

- `scripts/project-doc-site.spec.ts` — the `publishableImage > refuses a target whose real path escapes the repository` fixture links `packages/linked.png` as a **junction** to the outside directory instead of upstream's file symlink. `publishableImage` rejects an escaping reference on the realpath check (`inside === false` short-circuits before `statSync`), so a junction and a file symlink take the same branch, and on POSIX the junction type argument is ignored. Creating a file symlink needs the Windows developer-mode symlink privilege, and on this fork's Windows hosts file-symlink creation proved unreliable (EEXIST both under doc-sync concurrency and from bare processes) while junctions need no privilege and stayed stable. On merge, keep the junction call and its comment; if upstream reorders `publishableImage` to stat first, revisit which link kind still exercises the escaping branch.

- `docs/persistence-changes/2026-10-05-working-directory-attribution.{md,zh.md}` and `docs/persistence-changes/2026-10-16-instance-workspace-source-kind.{md,zh.md}` — the `previous` fields are rebased: 10-05 points to `2026-10-04-enterprise-attribution-kinds` (upstream declares `2026-09-21-user-question-reply`), and 10-16 points to `2026-10-13-user-rpc-principal` (it originally declared `2026-10-04-...`). The history must stay a linear chain per root; the enterprise records (10-04, 10-16) interleave with the upstream records (10-05, 10-07, 10-13) on the same four event roots, so each record's `previous` names the record that is its immediate predecessor in time, not the one its date suggests. After digest values are unchanged (they follow each record's own snapshot). On merge, re-derive the chain from the union of upstream and enterprise records by record date and re-check with `tsx scripts/persistence-changes.ts --check`; never accept a forked `previous`.

## Upstream merge procedure (enterprise fork)

After merging upstream `master`, resolve `pnpm-lock.yaml` with upstream's version, then expect a plain `pnpm install` to re-resolve: upstream's lock lacks the enterprise packages' importers, and filling them can pull freshly published type packages into the tree. Drifted `@types/*` or micromark-family versions break `typecheck` with two-version type clashes — `micromark-util-types` is pinned to 2.0.2 in `pnpm-workspace.yaml` overrides for exactly this (pnpm 11 no longer reads `pnpm` fields from `package.json`). When typecheck reports dependency-shaped type errors after an install, diff the working-tree lock against `HEAD` before touching code; and because `tsc -b` replays stale `.tsbuildinfo` diagnostics after pnpm relinks dependencies, clean with `tsc -b tsconfig.host.json --clean` (then `tsconfig.client.json`) and rebuild. Never leave the regenerated lock uncommitted — it carries the enterprise importers, and losing it to a checkout or stash recreates the whole failure.
